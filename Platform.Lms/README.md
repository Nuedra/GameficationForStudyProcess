# Граница данных LMS

Проект содержит прикладной контракт чтения данных LMS. Подсистема достижений не должна напрямую обращаться к таблицам людей, курсов, экземпляров курсов и зачислений.

Контракт опирается на проектную схему LMS:

- `LmsPerson` соответствует `Person.Persons`; текущая учебная группа является вычисляемой проекцией и не считается полем человека;
- `LmsCourseInstance` объединяет необходимые поля `Course.Courses` и `Course.CourseInstances`;
- активное зачисление соответствует `Course.CourseInstanceStudents` с учётом `StartDate` и `EndDate`.

До появления настоящей базы LMS используется `LocalLmsDataSource` из проекта `Platform.DataAccess.Postgress`. Он адаптирует существующие локальные таблицы и не определяет будущую физическую схему LMS.

Основной `ILmsDataSource` предназначен только для чтения. Достижения, критерии,
связи графа, факты получения и состояния уведомлений остаются собственностью
платформы достижений.

Для кабинета преподавателя и администратора выделен отдельный read-only
контракт `ILmsCourseManagementDataSource`. Он возвращает все экземпляры курса
для администратора, активные преподавательские назначения и отдельный экземпляр
для объектной проверки доступа. Текущая локальная таблица
`course_instance_teachers` является временной проекцией
`Course.CourseInstanceTeachers`: она входит только в `LocalLmsDbContext` и
локальный SQL-bootstrap, но не в `AchievementDbContext` и не в migrations
платформы достижений.

Изменение преподавательских назначений вынесено в отдельный командный контракт
`ILmsTeachingAssignmentDataSource`. Он позволяет прочитать назначения одного
экземпляра курса, сохранить назначение и завершить его без физического удаления
строки. Контракт не раскрывает EF-сущности. Будущий HTTP-адаптер LMS должен
реализовать именно этот порт, поэтому административный кабинет не зависит от
локальной таблицы или формата внешнего API.
